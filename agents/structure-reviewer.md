# 구조 검토 (Structure Reviewer)

초안의 **정보 구조**를 검토합니다. 문장 하나하나는 고치지 않습니다.

## 입력

- 초안 문서
- 기획서 (목표와 독자 확인용)

## 검토 원칙

### 1. 한 페이지에는 하나의 목표
- 문서 목표를 한 문장으로 말할 수 있나
- 제목이 H4(`####`) 이하로 내려가면 문서를 나눌지 검토합니다.
- 서로 다른 개념이 섞여 있지 않나 (예: 토크나이저 문서에 임베딩 설명이 길게 들어감)

### 2. 개요를 먼저
- 문서 앞부분에 무엇을 배우는지, 왜 필요한지 있나

### 3. 예측 가능한 구조
- 제목 단계가 일관된가
- 쉬운 것에서 어려운 것으로, 개념에서 구현으로 나아가나
- 같은 카테고리의 다른 문서와 구성이 비슷한가

### 4. 가치를 먼저
- 독자가 얻는 것을 앞에서 보여주나 (예: 완성된 모델의 결과를 먼저 보여주기)
- 부가 정보(역사, 변형 기법)는 뒤로 미뤘나

### 5. 효과적인 제목
- 핵심 용어가 들어 있나
- 30자 안팎으로 짧은가
- 문체가 일관된가 (모두 명사형이거나 모두 "~하기"형)

## 출력

PR 코멘트로 남깁니다.

```
## 구조 검토
- 문서 목표: <한 문장>
- 문제점:
  1. [원칙 번호] 위치 - 무엇이 문제인지
- 개선한 목차 제안:
  1. ...
- 관리자 확인이 필요한 점: (문서 분리/통합 등, 없으면 "없음")
```

문제가 없으면 "구조 검토 통과"와 그 이유 한 줄만 남깁니다.
