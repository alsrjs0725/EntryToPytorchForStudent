# 기획 (Planner)

새 문서를 시작하기 전에 **문서 유형과 목표**를 정합니다. 본문은 쓰지 않습니다.

## 입력

- [curriculum.md](curriculum.md)의 카테고리와 문서 목록
- 관리자의 요청 (주제, 강조할 점)
- 앞 문서들 (독자가 이미 아는 것을 확인하기 위해)

## 할 일

1. 문서가 커리큘럼의 어디에 들어가는지 정합니다. 앞뒤 문서와 겹치거나 빠진 내용이 없는지 확인합니다.
2. 아래 네 유형 중 **하나**를 고릅니다. 두 유형이 섞이면 문서를 나누자고 제안합니다.
3. 고른 유형의 체크리스트로 목차 초안을 만듭니다.

## 문서 유형

| 유형 | 목적 | 이 프로젝트에서의 예 |
| --- | --- | --- |
| 학습형 | 따라 하며 익히기 | 문자 단위 토크나이저 만들기, 띄어쓰기 모델 학습하기 |
| 설명형 | 원리 이해하기 | 어텐션은 왜 필요한가 |
| 문제 해결형 | 특정 문제 해결하기 | 손실이 줄지 않을 때 확인할 것 |
| 참조형 | 필요할 때 찾아보기 | 자주 쓰는 텐서 연산 정리 |

이 프로젝트는 대부분 **학습형**과 **설명형**입니다.

### 학습형 체크리스트
- 이 문서를 마치면 무엇을 할 수 있는지 첫머리에 적었나
- 필요한 사전 지식과 앞 문서 링크가 있나
- 단계마다 "무엇을"과 "왜"를 함께 설명하나
- 예제가 쉬운 것에서 어려운 것으로 나아가고, 모두 실행되나
- 독자가 막힐 만한 지점을 자주 묻는 질문으로 정리했나

### 설명형 체크리스트
- 이 개념이 없으면 어떤 문제가 생기는지 먼저 보여주나
- 원리를 코드나 그림으로 보여주나
- 다른 방법과 비교하나 (예: RNN과 어텐션)
- 실제로 어디에 쓰이는지 연결하나 (예: 다음 카테고리의 어떤 모델)

### 문제 해결형 체크리스트
- 문제 상황이나 증상이 분명한가
- 원인을 설명하나
- 해결 순서와 실행 가능한 코드가 있나
- 해결 방법이 왜 통하는지 설명하나

### 참조형 체크리스트
- 첫머리에 짧은 개요가 있나
- 인자의 타입, 기본값, 필수 여부를 적었나
- 반환값과 텐서 모양을 적었나
- 기본 예제와 응용 예제가 있나

## 출력

PR 설명에 다음 형식으로 남깁니다.

```
## 기획서: <문서 번호> <제목>
- 유형: 학습형
- 목표: 이 문서를 마치면 독자는 ~할 수 있다 (한 문장)
- 사전 지식: <앞 문서 링크>
- 목차 초안:
  1. ...
- 다음 문서와의 연결: ...
- 관리자 확인이 필요한 점: (없으면 "없음")
```
